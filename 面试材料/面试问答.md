# CampusTech 面试问答

> 按主题准备，不必背诵全文。回答结构建议：**结论 → 项目里怎么做 → 为什么这样设计**。

---

## 一、项目概述

### Q1：用 30 秒介绍一下这个项目

**答：** CampusTech 是一个面向学生的 **React 技术社区 SPA**，核心功能包括论坛帖子（富文本发帖）、两层评论、RSS 技术资讯和个人中心。前端用 React 19 + TypeScript + Vite，服务端状态用 TanStack Query，编辑器用 TipTap。我主要负责前端架构和交互，包括 XSS 防护、路由懒加载、统一 Loading/Empty/Error 状态，以及与 NestJS 后端的 REST 联调。

---

### Q2：你在项目里负责什么？团队多大？

**答：** 这是 **个人全栈项目，前端为主**。我独立完成前端页面、组件、路由、Query 数据层、富文本与安全渲染；后端用 NestJS 提供 API，我负责联调而不是深挖 Nest 模块设计。适合强调：**从 0 到 1 搭过完整社区前端**。

---

### Q3：为什么做这个项目？

**答：** 秋招需要一块能 **演示 + 深挖** 的前端作品。社区类场景天然覆盖：列表分页、表单、富文本、权限路由、评论树、搜索 debounce 等高频考点；同时可以做 XSS 和性能优化两个差异化故事，比 Todo List 更有面试说服力。

---

## 二、技术选型

### Q4：为什么用 TanStack Query，不用 Redux 或 useEffect？

**答：** 项目数据主要是 **服务端状态**（帖子列表、详情、评论、资讯），特点是异步、需缓存、会失效。Query 自带 loading/error、请求 dedupe、缓存键、`invalidateQueries`，比 `useEffect + useState` 少写样板代码，也避免重复请求。Redux 更适合大型全局客户端状态，本项目全局态主要是 **Auth Context**，用 Context + Query 足够，避免过度设计。

---

### Q5：为什么选 TipTap，不用 Quill / 原生 contenteditable？

**答：** TipTap 基于 ProseMirror，**扩展性好、TypeScript 友好**，和 React 集成成熟（`@tiptap/react`）。Quill 也可以，但 TipTap 更灵活，方便自定义字符数、图片上传、placeholder 等。选型的 trade-off 是 **bundle 较大**，所以后面做了动态 import，而不是换编辑器。

---

### Q6：为什么用 Vite 而不是 Webpack？

**答：** 个人项目追求 **开发体验和构建速度**，Vite 冷启动快、配置简单，对 React + TS 开箱友好。生产构建用 Rollup，也便于做 code split 分析。Webpack 更成熟但配置成本高，对这个体量 ROI 不高。

---

## 三、XSS 与富文本（高频深挖）

### Q7：XSS 是什么？你的项目怎么防？

**答：** XSS 是攻击者把恶意脚本注入页面，在其他用户浏览器里执行。帖子正文是 HTML，不能信任。我采用 **三层防护**：① 提交前 DOMPurify 白名单；② 后端 sanitize-html 再过滤后入库；③ 展示前 `RichTextContent` 再次 DOMPurify。标签、属性白名单一致，img 只允许 `/uploads/` 路径。

---

### Q8：只在前端过滤行不行？

**答：** **不行。** 攻击者可以绕过浏览器，直接用 Postman/curl 调 API 提交恶意 HTML。前端过滤只能防正常用户误操作或浏览器内篡改，**不能作为唯一安全边界**。后端必须在入库前消毒。

---

### Q9：只在后端过滤行不行？

**答：** **不够。** 后端能保证库里数据相对干净，但：① 可能有历史脏数据或其他写入入口；② 展示层仍应用 DOMPurify 做最后一道防线；③ 前端 Vitest 可以在 CI 回归 XSS 规则。纵深防御，任一层被绕过还有下一层。

---

### Q10：为什么 img 只允许 `/uploads/`？

**答：** 防止用户插入任意外链图床（追踪像素、违规内容、恶意重定向）。图片必须先走 **服务端上传 API**，拿到受控路径再插入编辑器，前后端都校验 `src` 前缀，形成闭环。

---

### Q11：`dangerouslySetInnerHTML` 安全吗？

**答：** 本身不安全，**关键看传入的 HTML 是否已消毒**。我只在 `RichTextContent` 里使用，且传入前经过 `sanitizePostHtmlForDisplay`。不会把 API 原始字段直接塞进去。

---

## 四、TanStack Query

### Q12：Query 的缓存键怎么设计？

**答：** 键必须包含 **影响请求结果的所有变量**。例如帖子列表 `['posts', page, category, keyword]`；我的帖子 `['posts', 'mine', userId, page]`；评论 `['comments', postId]`。这样分页、筛选、搜索互不污染。发帖成功后 `invalidateQueries({ queryKey: ['posts'] })` 刷新相关列表。

---

### Q13：为什么列表页设 `staleTime: 60_000`？

**答：** 帖子列表 60 秒内变化不频繁，同键请求在 stale 窗口内 **直接用缓存**，减少来回切分页/分类时的重复 HTTP，提升体验。详情页可以 staleTime 更短或默认 0，按业务调整。

---

### Q14：Loading、Empty、Error 为什么要分开？

**答：** 用户心理不同：**Loading** 是「请等待」；**Empty** 是「没有数据，可能要去创作」；**Error** 是「出问题了，可以重试」。混用「加载中」和「暂无数据」会让用户困惑。Empty 带引导按钮（如「去发帖」），Error 带 `refetch`，都是 UX 细节。

---

## 五、路由与权限

### Q15：路由怎么划分？懒加载做了什么？

**答：** 公开路由：首页、帖子列表/详情、资讯、用户主页。受保护路由：`ProtectedRoute` 包裹发帖、编辑、个人中心，未登录跳 `/login` 并带 `from`。`GuestRoute` 防止已登录用户再进登录页。重页面 `PostCreatePage`、`PostDetailPage`、`ProfilePage` 等用 `React.lazy` + `Suspense`，fallback 是 `LoadingSpinner`。

---

### Q16：JWT 存在哪？怎么鉴权？

**答：** Token 存 **localStorage**（通过 `utils/token` 封装），`AuthProvider` 启动时 `getMe` 恢复用户态。Axios 拦截器带 Authorization 头。`ProtectedRoute` 读 Context 的 `isAuthenticated`。登出清 token + 清 user。

**追问：localStorage 和 httpOnly Cookie 的区别？**  
localStorage 易受 XSS 读取；httpOnly Cookie 防 JS 读取但需防 CSRF、跨域配置更复杂。个人项目用 JWT + localStorage 简单可行，生产会评估 Cookie + CSRF 方案。

---

### Q17：非作者编辑帖子怎么拦截？

**答：** 前端 `PostEditPage` 拉详情后比对 `author.id` 与当前用户，非作者 `<Navigate>` 回详情页并提示「无权编辑」。这是 **UX 层拦截**，真正权限在后端 API 也要校验（面试可补一句「前端守卫不能替代后端鉴权」）。

---

## 六、性能优化

### Q18：你做了哪些性能优化？效果如何？

**答：** ① 路由 lazy load 拆分详情/发帖/个人中心；② `LazyPostEditor` 动态 import TipTap；③ 校验函数抽到 `postEditorValidation.ts`，避免页面静态依赖编辑器 bundle；④ PostCard `React.memo`、封面 `loading="lazy"`；⑤ 列表 `staleTime`。主 chunk 从 **~803 KB 降到 286 KB（约 -64%）**，TipTap 独立 ~408 KB chunk，列表首屏不下载编辑器。

---

### Q19：为什么 TipTap 要 code split？

**答：** TipTap + ProseMirror **体积大**，但只有发帖/编辑两个页面需要。打进主 bundle 会拖慢首屏（列表、首页是高频路径）。动态 import 后，用户浏览帖子时不加载编辑器，发帖时才拉 chunk，是 **按路由拆分** 的典型场景。

---

### Q20：怎么验证优化有效？

**答：** `npm run build` 看 `dist/assets` 各 chunk 体积；DevTools Network 看列表页是否加载 `PostEditor-*.js`；写了 `verify-subtask-h.mjs` 自动化验收；Vitest 保证功能不回退。

---

## 七、功能与交互

### Q21：搜索 debounce 怎么实现？

**答：** 输入框用 `useState` 存即时值，经 `useDebounce(value, 300)` 得到 debounced 值，**只有 debounced 值进入 Query 的 queryKey**。避免每敲一个字就请求 API。关键词变化时 reset 到第 1 页。

---

### Q22：Profile 双 Tab 和 URL 深链怎么做？

**答：** `ProfilePage` 用 `useSearchParams` 读 `tab`，默认 `settings`，`?tab=posts` 显示我的帖子。切换 Tab 时 `setSearchParams` 更新 URL，支持刷新保持 Tab、分享链接。`MyPostsList` 单独 Query 键按 `authorId` 筛帖。

---

### Q23：评论两层回复怎么展示？

**答：** API 返回平铺或带 `parentId` 的数据，前端组装树形或按 parent 分组渲染。点击「回复」展开 `CommentForm`，`parentId` 指向被回复评论。Query 键 `['comments', postId]`，提交成功后 invalidate 刷新。

---

### Q24：图片上传怎么做的？

**答：** 封面和正文插图用 **FormData** 调上传 API，后端存 `/uploads/` 目录，返回相对路径。编辑器插入 `<img src="/uploads/...">`，与 XSS 白名单策略一致。前端限制文件类型和大小（如 2MB、jpeg/png/webp）。

---

**答：** ① 评论 **乐观更新** 提升发帖体验；② 长列表 **虚拟滚动**；③ 表单换 **React Hook Form** + Zod 校验；④ 线上 Demo 部署；⑤ E2E（Playwright）覆盖主流程。按面试岗位选 1–2 个展开即可，体现你有迭代思路。

## 九、难点与反思

### Q27：项目里遇到的最大难点？

**答（示例）：** **富文本安全渲染链路**。一开始只在前端 DOMPurify，后来意识到 API 可被直接调用，补了后端 sanitize；又发现 img 外链问题，加了 `/uploads/` 限制和 DOMPurify hook。最后用 Vitest 把规则固定下来。这个过程让我理解 **安全不能靠单点**。

---

### Q28：有什么做得不够好、如果重做会改什么？

**答（诚实加分）：** ① Token 放 localStorage，生产会更评估 Cookie 方案；② 部分页面状态还可抽 custom hooks；③ E2E 覆盖不足，目前 Vitest 偏单元/组件；④ 评论未做乐观更新。能说出不足并给出改进方向，比假装完美更好。
