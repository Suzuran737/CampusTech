# CampusTech 前端架构说明

> 路由怎么分、状态放哪、Query 键怎么设计、性能优化做了什么。

## 1. 路由结构

```
/                     HomePage（公开）
/posts                PostListPage（公开，含 debounce 搜索）
/posts/:id            PostDetailPage（公开，lazy）
/articles             ArticleListPage（公开）
/users/:username      UserProfilePage（公开）
/login, /register     GuestRoute 包裹（已登录则重定向）
/posts/new            ProtectedRoute + PostCreatePage（lazy）
/posts/:id/edit       ProtectedRoute + PostEditPage（lazy，非作者 Navigate 拦截）
/profile              ProtectedRoute + ProfilePage（lazy，Tab 深链 ?tab=posts）
*                     NotFoundPage
```

| 类型 | 组件 | 作用 |
| --- | --- | --- |
| 公开路由 | 直接渲染 | 未登录可浏览列表/详情/资讯 |
| `ProtectedRoute` | 检查 JWT + `useAuth` | 未登录 → `/login`，并保存 `state.from` |
| `GuestRoute` | 反向守卫 | 已登录访问登录/注册页 → 重定向首页 |
| 404 | `path="*"` | 友好 NotFoundPage，非硬跳转 |

**重页面懒加载**：`PostCreatePage`、`PostEditPage`、`PostDetailPage`、`ProfilePage` 使用 `React.lazy` + `Suspense`，fallback 为 `LoadingSpinner`。

## 2. 状态分层

| 类别 | 方案 | 示例 |
| --- | --- | --- |
| **服务端状态** | TanStack Query | 帖子列表、详情、评论、资讯、我的帖子 |
| **全局客户端状态** | React Context | `AuthProvider`：user / login / logout |
| **局部 UI 状态** | `useState` | 搜索框输入、评论回复展开、表单字段 |
| **URL 驱动 UI** | `useSearchParams` | Profile Tab：`?tab=posts` |

**为什么列表不用 useEffect + useState？** Query 自带缓存、重试、loading/error 态、请求 dedupe；切换分页/分类时可直接复用缓存（配合 `staleTime`）。

## 3. Query 缓存键设计

原则：**键必须唯一标识一次请求的所有变量**。

| 场景 | queryKey | queryFn 参数 |
| --- | --- | --- |
| 帖子列表 | `['posts', page, category, keyword]` | `getPosts({ page, pageSize, category, keyword })` |
| 我的帖子 | `['posts', 'mine', userId, page]` | `getPosts({ authorId, page, pageSize })` |
| 帖子详情 | `['post', id]` | `getPost(id)` |
| 评论 | `['comments', postId]` | `getComments(postId)` |
| 资讯 | `['articles', page, source]` | `getArticles(...)` |

**失效策略示例**：发帖成功后 `queryClient.invalidateQueries({ queryKey: ['posts'] })`，列表与「我的帖子」一并刷新。

**列表优化**：`PostListPage` 设置 `staleTime: 60_000`，60 秒内同键请求直接读缓存，减少重复 HTTP。

## 4. 组件分层

```
frontend/src/
├── pages/          路由级页面，组合组件与 Query
├── components/     可复用 UI（PostCard、EmptyState、RichTextContent…）
├── components/profile/  个人中心子模块
├── hooks/          useAuth、useDebounce
├── api/            Axios 封装，与后端 REST 一一对应
├── types/          Post、User 等共享 TS 类型
├── lib/            TipTap 扩展、DOMPurify 封装
└── utils/          纯函数（errors、resolveAssetUrl、校验）
```

页面负责「编排」，组件负责「展示」，`api/` 负责「数据获取」，避免在组件内散落 fetch 逻辑。

---

## 5. 评论交互（楼中楼）

- 一级评论 + **扁平回复列表**（B 站风格，无多层缩进）
- 回复非楼主时展示 `回复 @昵称：内容`
- 回复超过 3 条默认折叠，可展开/收起
- 后端 `parentId` 存关系，API 返回拍平后的 `replies` + `replyTo`

## 6. 性能优化（子任务 H）

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 主 chunk | ~803 KB（含 TipTap，>500KB 警告） | **286 KB** |
| TipTap | 打入主 bundle | **408 KB** 独立 chunk，仅发帖/编辑加载 |
| 主 chunk gzip | — | **89 KB**（约 **-64%**） |

**手段**：
1. 路由 `React.lazy` — 详情/发帖/个人中心按需加载
2. `LazyPostEditor` 动态 import TipTap — 列表页首屏不下载编辑器
3. `postEditorValidation.ts` 与编辑器解耦 — 避免页面静态依赖 TipTap
4. `PostCard` `React.memo` + 封面 `loading="lazy"`
